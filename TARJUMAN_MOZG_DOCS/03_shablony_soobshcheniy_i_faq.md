## 1. Каналы коммуникации с клиентом

1. **Сайт** (tarjumanedu.com) — заявки, статусы, дашборд, оплата.
2. **Telegram-бот** — основной канал живого общения с клиентом (регистрация, FAQ, статус заявки, чат с менеджером).
3. **Email** — используется для части системных уведомлений (см. `payment-success`, `reminders/payment`).
4. **Форма на /contact — НЕ функциональна** (заглушка, ничего никуда не отправляет).

Реальное общение с клиентом идёт **преимущественно через Telegram-бота**, с параллельным дублированием части уведомлений на email.

## 2. Telegram-бот — архитектура

Бот — отдельная система с собственными файлами (`src/lib/bot/*`), не связана напрямую с UI сайта, но использует ту же БД Supabase.

### 2.1 Конфигурация (`src/lib/bot/config.ts`)
- `BOT_TOKEN` — токен бота (переменная окружения `TELEGRAM_BOT_TOKEN`)
- `ADMIN_CHAT_ID` — chat_id администратора для получения уведомлений о новых заявках
- `MANAGER_TG = 'TARJUMAN_EDU'` — юзернейм менеджера для прямых обращений клиентов
- `SITE_URL = 'https://tarjumanedu.com'`
- Поддерживаемые языки бота: ru / uz / en (тип `Lang`)
- Статусы лида в CRM-логике бота (`Status` тип): `new` → `in_progress` → `waiting` → `done` (циклический переход через `STATUS_NEXT`)

### 2.2 Дедупликация уведомлений
В эндпоинте `new-application/route.ts` реализована in-memory защита от дублей: если по одной заявке уведомление уже отправлено за последние 10 минут — повторное не отправляется. Также есть защита: уведомление о новой заявке не отправляется, если заявка старше 5 минут (защита от повторной отправки по историческим данным).

### 2.3 Клавиатуры бота (`src/lib/bot/keyboards.ts`)
Инлайн-клавиатуры: главное меню (mainMenu), меню "назад" (backMenu), меню контактов (contactMenu), выбор языка (langSelectMenu), меню действий с лидом для админа (leadActionsMenu), меню отмены (cancelMenu).

### 2.4 Обработчики (`src/lib/bot/handlers/`)
- **user.ts** (143 строки) — сценарий /start, определение языка, привязка заявки по deep-link (если пользователь пришёл с сайта по специальной ссылке), роутинг по FAQ-меню.
- **admin.ts** (240 строк) — админ-команды `/clients`, `/client`, `/stats`; машина состояний для ответа менеджера клиенту и заметок; продвижение статуса лида.

### 2.5 CRM-функции бота (`src/lib/bot/database.ts`)
Функции: upsertUser, getUserLang/setUserLang, getClients/getClientCount, upsertLead/getLeadByChatId/updateLeadStatus/updateLeadNotes/getLeadStats, работа с состоянием админ-сессии, logMessage (журналирование сообщений).

## 3. Полные шаблоны сообщений бота (`src/lib/bot/translations.ts`, ru/uz/en)

Ключевые пресеты сообщений (структура `translations.ts`, 178 строк):
- `welcome_new` — приветствие нового пользователя, который пишет боту впервые (без привязки к существующей заявке).
- `welcome_app` — приветствие пользователя, который перешёл по deep-link с существующей заявкой на сайте (бот узнаёт его и привязывает Telegram chat_id к аккаунту).

- `contact_user` — шаблон для передачи контакта менеджера клиенту.

(Точный посимвольный текст каждого шаблона на трёх языках содержится в файле `src/lib/bot/translations.ts` — при переносе в новый проект рекомендуется скопировать файл целиком, так как это самый плотный источник готовых клиентских формулировок во всём проекте.)

## 4. Шаблоны Telegram-уведомлений о статусах заявки (`src/app/api/notifications/status-change/route.ts`)

Полный маппинг статусов на клиентские сообщения (эмодзи + текст на русском):

| Статус | Эмодзи | Текст клиенту |
|---|---|---|
| `PAID` | 💳 | «Ваша оплата подтверждена! Мы начинаем работу над вашей заявкой.» |
| `IN_PROGRESS` | ⚙️ | «Ваши документы приняты в работу. Мы переводим и проверяем их.» |
| `UNDER_REVIEW` | 🔍 | «Ваши документы проходят финальную проверку перед отправкой в университет.» |
| `SUBMITTED` | 📬 | «Ваша заявка отправлена в университет! Ожидайте ответ в течение 2–4 недель.» |
| `COMPLETED` | 🎉 | «Поздравляем! Ваша заявка успешно завершена.» |
| `REJECTED` | ❌ | «К сожалению, по вашей заявке пришёл отказ. Свяжитесь с менеджером.» |

Формат итогового сообщения:
```
{emoji} Статус заявки обновлён

{full_name}

{текст статуса}

https://tarjumanedu.com/dashboard
```

Логика: сервер получает `applicationId` + `newStatus`, подтягивает `full_name` и `telegram_chat_id` из БД (join `applications` → `users`), если чат ID есть — отправляет сообщение через `sendMessage` Telegram Bot API напрямую (fetch на `api.telegram.org`).

Направление: {🇸🇦 Саудовская Аравия | 🇦🇪 ОАЭ}

Отслеживать статус: https://tarjumanedu.com/dashboard
```

### 5.2 Администратору (всегда)
```
📋 Новая заявка!

Имя: {full_name}
Телефон: {phone или "—"}
Telegram: {@telegram или "—"}

## 6. Прочие уведомления (по названиям эндпоинтов, из ранее просмотренных файлов)
- `api/notifications/payment-success/route.ts` — уведомление об успешной оплате (Telegram + email).
- `api/reminders/payment/route.ts` — напоминание клиенту о неоплаченной заявке.
- `api/admin/broadcast/route.ts` — массовая рассылка сообщений всем клиентам от администратора (защищено заголовком `x-admin-key`).
- `api/admin/start-processing/route.ts` — при переводе заявки в `IN_PROGRESS`, вероятно, отправляет соответствующее уведомление и запускает side-effects.
- `api/admin/complete-processing/route.ts` — при переводе в `SUBMITTED`, аналогично.

(Точные тексты этих шаблонов зафиксированы в предыдущей фазе разбора кода в этой же сессии; при переносе в TARJUMAN MOZG рекомендуется скопировать сами файлы `route.ts` целиком, так как это самый надёжный источник точных формулировок.)

## 9. Правила общения с клиентами (реконструировано из кода и текстов)

1. **Тон** — дружелюбный, но профессиональный; используются эмодзи в статусных уведомлениях (💳⚙️🔍📬🎉❌) для визуальной ясности статуса.
2. **Многоязычность** — все клиентские тексты должны существовать минимум на 3 языках: русский (ru), узбекский (uz), английский (en). Это системное требование всего проекта — ни один шаблон не должен быть только на одном языке.
3. **SLA на ответ менеджера** — обещание "24 часа" на связь после подачи заявки; обещание "3 рабочих дня" на ответ по запросу возврата.
4. **Никогда не обещать гарантию поступления** — фраза "решение принимает университет" должна присутствовать в любом сообщении, где обсуждается вероятность зачисления.
5. **Всегда давать ссылку на дашборд** (`https://tarjumanedu.com/dashboard`) в статусных уведомлениях, чтобы клиент мог отслеживать прогресс самостоятельно.
6. **Разделение админ/клиент** — уведомления администратору (в `ADMIN_CHAT_ID` и через `TELEGRAM_ADMIN_CHAT_ID`) идут отдельным, более техническим сообщением (с ID заявки, телефоном, тарифом), в отличие от тёплого клиентского сообщения.
7. **Дедупликация** — система явно защищена от отправки дублирующих уведомлений (10-минутное окно), это принцип, который стоит сохранить и в AI-агентах нового проекта, чтобы не спамить клиента.
